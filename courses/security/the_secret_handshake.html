Lecture notes · Information security

The Secret Handshake

Two people share a secret. How can they use it to prove that a message really came from the other one, and that nobody changed it on the way? That's what a MAC does, and HMAC is the most popular way to build one. No math needed.

★ Explain like I'm five

The twin stamps

Barney and Bella have two identical magic stamps. Nobody else in the world has one. The seal a stamp makes depends on the words of the letter.

  • 1Barney stamps his letter. The shared stamp is the secret key, and the seal is the tag.
  • 2Bella stamps the same words with her copy. Same stamp + same words = same seal. So the letter is from Barney and unchanged.
  • 3If Can changes a word, Bella's seal comes out different. Caught!
  • 4The catch: Bella could have made that seal too. So she can't prove to anyone else that Barney wrote it.
Now in grown-up words
In the storyIn computer security
The two identical stampsOne shared secret key, known to both sides
The seal on the letterThe MAC tag, a short code sent with the message
Bella stamping her own copy and comparingRecomputing the tag and checking that it's the same
Can changing a wordTampering, which makes the tags differ

1 · The problem

Why a hash isn't enough

From the hashing lecture: a hash is a fingerprint of a message. If the message changes, the fingerprint changes. So why not just send the message with its fingerprint? Watch what a cheater can do.

A fingerprint catches accidents. To catch cheaters, we need a secret ingredient that Can doesn't have.

2 · The fix

What a MAC is

A MAC (Message Authentication Code) is a fingerprint that also needs a secret key to make. Barney and Bella agreed on the key beforehand, and nobody else knows it.

InputThe message + the shared secret key.
OutputA short code called the tag (sometimes also called "the MAC").
RuleWithout the key, nobody can make the right tag for a message.

Notice the difference from signatures

Here there's only one key, and both sides use it for everything. Making the tag and checking it are the same action, done twice.

4 · Clearing up the names

MAC vs HMAC

MAC is the idea. HMAC is one specific recipe for building that idea out of a hash function.

The general idea MAC

Any method that makes a tag from a message and a secret key. It's a category, like "hot drink".

Says what it does, not how it's built.

One specific recipe HMAC

A MAC built from a hash function such as SHA-256. It's one item in the category, like "Turkish tea".

H stands for Hash. "HMAC-SHA256" means the HMAC recipe using SHA-256.

Every HMAC is a MAC, but not every MAC is an HMAC. Here's the MAC family:

5 · Under the hood, gently

How HMAC works

The obvious idea is to glue the key to the message and hash it: fingerprint of (key + message). Surprisingly, with hashes like SHA-256 that's not safe. Watch why.

HMAC fixes this by hashing twice, with the key mixed in each time. The outer hash wraps the inner one like a sealed envelope, so there's no "bookmark" left for Can to continue from.

You don't need to memorize the recipe

Programming languages already include HMAC (for example hmac in Python or crypto.createHmac in Node.js). The lesson is: don't invent your own MAC. Use HMAC.

6 · Connecting the lectures

MAC vs digital signature

Both protect against tampering. The big difference is the keys.

MAC / HMACDigital signature
KeysOne shared secret keyA key pair: private signs, public checks
Who can check it?Only people who have the secret keyAnyone with the public key
Proves who sent it?Only to the other key holderTo everyone
Non-repudiationNo: both sides could have made the tagYes: only the private key owner could sign
SpeedVery fastSlower
Typical useTwo parties who already share a key, e.g. your app and its serverMessages for the whole world, e.g. software updates, websites, e-İmza
Rule of thumb

Talking privately with someone you share a secret with? Use a MAC. Need anyone, including a judge, to be able to check? Use a signature.

7 · Everyday life

Where you use MACs every day

WhereWhat the MAC does
Authenticator app codesThe 6-digit codes in Google Authenticator and similar apps are made with HMAC from a secret shared with the website, plus the current time.
HTTPS (the padlock)After the connection starts, every piece of data carries a tag, so changes on the way are caught.
Login tokensMany websites keep you logged in with a token (often a JWT) protected by HMAC, so you can't edit it to become admin.
Webhooks and APIsServices like GitHub and payment providers attach an HMAC-SHA256 tag to messages they send, so the receiver knows they're real.
Wi-Fi and VPNsData packets carry tags so they can't be changed in the air.
8 · Weak spots

What can go wrong

  • The key leaks. Two people hold the same secret, so there are two places it can leak from. Whoever has the key can make valid tags.
  • A weak key. Keys like "password123" can be guessed. Use long, random keys.
  • Replay. Can can't change the message, but he can send the same valid message again. "Transfer 100 TL" ten times! The fix is to include a counter or a timestamp in the message.
  • Thinking a MAC hides the message. It doesn't. Anyone can read the message. For secrecy, you also need encryption.
  • Inventing your own. Fingerprint of (key + message) looks fine but falls to the add-on attack. Use HMAC.

10 · Glossary

Key terms

MACMessage Authentication Code. Any method that makes a tag from a message and a secret key.
HMACA specific MAC recipe built from a hash function. H = Hash.
TagThe short code a MAC produces. Sent along with the message.
Shared secret keyOne key both sides know and nobody else does.
IntegrityThe message wasn't changed.
AuthenticityThe message came from someone who has the key.
Length-extension attackAdding text to a message and its naive fingerprint without knowing the key.
Replay attackSending an old valid message again.
Non-repudiationBeing unable to deny sending. MACs don't give this; signatures do.
In-class activity (10 min)

In pairs, agree on a secret word. Write a short message, and as a "tag" write the secret word's first letter after every third word of the message. Swap with another pair and try to change their message without being caught. Then discuss: what made it easy or hard? Why is a real MAC much harder to fool than this game?
